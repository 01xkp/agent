# Day 1 概念笔记

这份笔记用尽量少的术语解释 Week 1 的基础概念。

## Token

Token 是模型读写文字时使用的基本单位，不严格等于一个汉字或一个英文单词。输入和输出都会占 Token，并影响上下文容量、费用和延迟。例如“AI 工程”可能被切成多个 Token，实际数量应以供应商统计为准。

## 上下文窗口

上下文窗口是模型一次请求能看到的全部 Token 上限，包含 System Prompt、历史对话、当前问题、工具结果和模型输出。超过限制可能报错或丢失旧信息。上下文越长，费用和首 Token 时间通常也越高，所以本项目只发送最近 4 轮。

## Temperature 与 Top-p

两者都影响采样随机性。Temperature 越高，回答通常越发散；事实问答、代码和 JSON 更适合低值。Top-p 从概率最高的一组候选中采样。初学时一次只改一个变量，否则无法判断结果变化来自哪里。

## 停止条件

模型可能因为正常结束、达到最大输出 Token、用户中止、超时、网络断开或内容安全限制而停止。程序不能假设所有停止都代表回答完整，必须检查错误、结束原因和结构化输出是否通过校验。

## Tokenization 的直觉

Tokenization 像把一句话切成模型认识的小积木。不同模型的切法可能不同，中文、英文、代码、网址和 JSON 的 Token 密度也不同。因此不能只用字符数精确推算成本，本项目的离线估算只用于 Mock 教学。

## Embedding 的直觉

Embedding 是把文字变成一组数字，让语义接近的内容在数字空间里更接近。它常用于检索，不等于聊天模型生成。项目 Week 3 的哈希向量是离线教学实现，不是真实 Embedding API。

## Attention 的直觉

Attention 可以理解为模型生成当前 Token 时，对上下文不同位置分配不同关注度。它不是人类意识，也不能保证模型关注了最重要的事实。长上下文仍可能稀释关键信息，因此需要裁剪、摘要和检索。

## 幻觉与非确定性

幻觉是模型生成了流畅但没有依据或不正确的内容。非确定性表示同一问题可能得到不同回答。降低 Temperature、提供明确边界、要求引用、使用结构校验和固定 Eval 能降低风险，但不能完全消除。

## 模型能力、速度、价格的权衡

通常不存在能力最强、速度最快、价格最低同时成立的模型。普通聊天可先用 Mini、Flash 或非推理模型，复杂任务再切换大模型。应记录质量、首 Token、总延迟、Token 和价格，而不是只看模型名称。
## 不看资料自测

1. 为什么同一问题可能得到不同回答？
2. 为什么上下文越长不一定越好？
3. 为什么不能把流畅度当作正确率？
4. 首 Token 时间和总延迟分别影响什么体验？
5. 如何设计只改变一个变量的模型对比实验？

参考答案：

1. 模型按概率采样，参数和服务状态也会变化；
2. 长上下文增加计算量，还可能稀释重点；
3. 文字流畅不能证明事实正确；
4. 首 Token 决定开始响应的体感，总延迟表示完整完成时间；
5. 固定 Prompt、参数、数据和运行环境，只替换一个模型或一个参数。
